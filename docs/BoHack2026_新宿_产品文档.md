# 新宿智能反应釜边缘上位机产品文档

## 1. 项目一句话

新宿是一套运行在 A55 工控板上的智能反应釜边缘上位机：把实验室反应釜、摇瓶或小试设备的传感器数据、工艺配方、批次结果和 AI 推荐闭环在本地完成，让小试研发从“人工盯数、纸面记录、经验调参”升级为“真实数据驱动、可审计、可解释、可离线运行”的智能工艺操作系统。

## 2. 项目背景与真实痛点

实验室和中试阶段的化学、生物制造、材料研发经常面临三类问题：

1. 数据断裂：温度、压力、搅拌、摇瓶速度、流量、浓度、pH 等过程数据分散在不同仪表、串口工具或人工记录中，批次结果和过程曲线难以对应。
2. 调参依赖经验：下一批温度、搅拌、加热时间、保温时间通常依赖工程师经验，历史批次无法快速沉淀成可复用策略。
3. 智能化落地困难：很多 AI 工艺优化方案停留在云端分析或离线报告，缺少对真实设备的安全边界、数据质量、现场离线运行和审计追踪。

新宿的定位不是替代反应釜本体保护，而是补齐“实验设备到智能决策之间”的边缘控制层：低层设备负责实际加热、搅拌和联锁保护，新宿负责采集、记录、分析、推荐和经过安全边界校验的目标下发。

## 3. 目标用户与应用场景

目标用户包括高校实验室、合成生物 / 新材料 / 精细化工研发团队、小试生产线、设备集成商和智能制造实训平台。

典型场景：

1. 小试反应釜批次优化：记录每一批的过程曲线和产率，AI 推荐下一批目标参数。
2. 摇瓶 / 摇罐过程监测：通过二值倾角传感器与摇瓶速度拟合趋势曲线，监控固定、震荡和异常状态。
3. 设备改造上位机：通过 ESP32 串口、Modbus RTU 或 JSON Bridge 接入既有设备，低成本形成可视化 HMI。
4. 离线工业现场：在无公网或网络不稳定场景下，本地 SQLite、边缘服务和本地优化器仍可运行。

## 4. 产品核心能力

### 4.1 真实数据 HMI

Web HMI 展示实时温度、压力、搅拌转速、摇瓶速度、倾角拟合、流量、产物浓度和 pH；同时提供趋势图、设备状态、报警、批次历史、工艺配方、AI 建议和系统设置。

关键原则：生产传感器数据不造假。没有真实 pipeline / ESP32 / JSON Bridge 输入时，`/api/live` 返回 503，页面显示管线错误和空值，而不是填充演示假数据。

### 4.2 工艺配方与批次闭环

系统支持创建工艺定义、添加多个工艺步骤、启动工艺、停止当前批次、记录产品结果，并将批次目标参数、传感器样本和控制事件存入 SQLite。

这让用户能够回答三个问题：

1. 这一批当时怎么跑的？
2. 这一批的结果如何？
3. 下一批应该怎么改？

### 4.3 AI 推荐与可解释优化

系统内置本地轻量优化器，并可选接入 StepFun `step-3.6`。AI 推荐基于历史批次、文件型 AI memory、参考批次、目标权重和禁区边界生成下一批参数，包括目标温度、搅拌转速、加热时间和保温时间。

安全设计：

1. 推荐只能给批次级 setpoint，不直接绕过设备执行器。
2. 推荐参数必须落在安全边界内。
3. 推荐落入禁区时自动回退本地优化器。
4. 外部模型超时、无 key、异常输出时不影响系统运行。

### 4.4 安全门控与审计

新宿在控制链路上实现急停、人工锁定、自动控制开关、传感器超时检查、温度上限、转速上限和单次调整步长限制。

每次控制下发都会记录 `control_events`，包括事件类型、目标温度、目标转速、目标摇瓶速度、批次 ID 和原因，便于现场复盘。

### 4.5 多硬件接入

当前实现支持四种设备模式：

1. Pipeline：外部数据管线通过 API 写入样本。
2. ESP32 Serial：ESP32 通过 ASCII 串口帧上报传感器数据，树莓派下发目标参数。
3. JSON Bridge：下游桥接程序写 `state.json`，新宿原子写 `control.json`。
4. Modbus RTU：为工业设备寄存器读写预留适配。

项目已包含 ESP32 协议文档、JSON Bridge 文档、示例固件、A55 Debian 10 构建脚本、Chromium kiosk 和 Qt HMI shell。

## 5. 技术架构

```text
传感器 / 执行器
        |
ESP32 / Modbus / JSON Bridge / 数据管线
        |
reactor-edge-daemon (Rust + Tokio + Axum)
        |
SQLite + Safety Gate + AI Memory + Optimizer
        |
HTTP API / WebSocket / Web HMI / Kiosk
```

后端是 Rust 单进程边缘服务，负责设备采集、控制循环、API、静态 HMI 托管、SQLite 持久化和 AI 推荐。前端是单文件 Web HMI，便于在低功耗板卡上部署。部署形态支持 Docker、本机二进制、systemd、Chromium kiosk 和 Qt shell。

## 6. 技术完整性

已实现的 demo 核心功能：

1. 实时数据采集与展示：温度、压力、搅拌、摇瓶、倾角拟合、流量、浓度、pH。
2. 工艺配方管理：创建工艺、添加步骤、启动 / 停止批次。
3. 安全控制：急停、人工锁、自动控制开关、传感器超时、上下限和步长限制。
4. AI 推荐：本地优化器 + 可选 StepFun，带禁区、边界、参考批次和回退机制。
5. 本地持久化：SQLite 保存传感器样本、批次、产品结果、控制事件和 AI 推荐。
6. 硬件接入：ESP32 串口协议、JSON Bridge、Modbus RTU 适配基础。
7. 工业部署：A55 Debian 10 交叉构建包、systemd 服务、Chromium kiosk、Qt HMI shell。
8. 自动化测试：Rust API / 控制 / 数据库 / 协议测试，Playwright 桌面与移动端 E2E。

架构合理性：

1. 设备层与上位机层解耦，降低接入不同硬件的成本。
2. AI 建议与执行控制分层，避免模型直接驱动危险设备。
3. 真实数据优先，缺数据时显式失败，符合工业现场可信原则。
4. 边缘部署可离线运行，适合实验室和小试现场。

## 7. 创新性与差异化对照

新宿的差异化不是再做一个仪表盘，而是把“过程数据、批次结果、AI 推荐、安全边界、设备控制”做成闭环。

创新点：

1. 真实数据管线优先：演示系统也不伪造生产传感器读数，强调可审计可信。
2. AI memory 文件化：参考批次、禁区、目标权重、传感器阈值以配置文件形式管理，便于工艺专家参与调优。
3. AI 推荐可回退：外部大模型是增强项，本地优化器保证无网也可用。
4. 二值倾角拟合：只需低成本二值倾角传感器，结合摇瓶速度拟合趋势，用于可视化与报警。
5. JSON Bridge 低侵入改造：对已有串口桥接程序，只需读写 `state.json` / `control.json`，即可接入上位机。
6. 面向实验批次的智能闭环：不是单点监控，而是把“本批怎么跑、结果如何、下一批怎么改”连起来。

## 8. 商业价值对照

### 9.1 解决的真实难题

实验室自动化往往卡在最后一公里：设备数据拿不到、历史数据不成体系、AI 建议无法安全落地。新宿把低成本硬件接入、边缘 HMI、批次数据库和 AI 推荐合成一个可部署产品。

### 9.2 产品化路径

第一阶段：作为实验室智能上位机套件交付，包括边缘盒子、传感器接入、Web HMI、批次管理和 AI 推荐。

第二阶段：面向设备厂商提供 SDK / Bridge 方案，让老设备通过 JSON Bridge 或串口协议快速智能化。

第三阶段：形成跨实验室的工艺知识库，把本地 AI memory 与云端模型服务结合，提供更强的参数推荐、异常诊断和工艺迁移能力。

### 9.3 商业模式

1. 硬件网关 + 软件授权：按设备或产线售卖边缘盒子与 HMI 授权。
2. 设备集成服务：为实验室和小试线做传感器、串口、Modbus 接入。
3. AI 优化订阅：按项目或设备提供模型推荐、工艺知识库和报告服务。
4. 教育与实训：作为智能制造、合成生物、自动化控制课程平台。

### 9.4 市场空间

潜在客户覆盖科研实验室、小试中试平台、合成生物与材料研发企业、化工设备厂商、职业教育和高校实训中心。相比采购完整工业 DCS / SCADA，新宿更轻量、部署成本更低，更适合从单台设备开始改造。

## 9. 评委可能关心的问题

问：这是不是只做了一个漂亮前端？

答：不是。后端已经实现设备抽象、控制循环、SQLite 持久化、安全门控、批次生命周期、AI 推荐和多协议接入。前端只是 HMI 入口。

问：AI 会不会直接控制危险设备？

答：不会。AI 只给批次级建议，所有目标参数都经过安全边界、禁区和控制门控校验，急停、人工锁、传感器超时都会阻断下发。

问：没有网络或大模型失败怎么办？

答：系统默认有本地优化器，StepFun 只是增强项。无网、无 key、超时或模型输出异常时，自动回退本地推荐。

问：现场 demo 没有真实反应釜怎么办？

答：可以用 pipeline 或 JSON Bridge 输入真实格式的模拟硬件帧，系统仍然坚持“不造生产读数”。缺失数据会明确报错，写入真实样本后恢复展示和历史记录。

问：为什么适合黑客松？

答：它兼顾了可运行 demo、硬件接入、AI 创新、安全工程和商业化方向，不是单一页面原型，而是一个可继续产品化的边缘智能系统。
