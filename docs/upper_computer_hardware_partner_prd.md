# 星宿智能反应釜硬件伙伴联调 PRD

日期：2026-06-12

版本：v0.1

对象：硬件控制器、传感器、执行器、RS485/串口链路、现场电气与固件负责人

相关上位机状态：当前上位机主体软件已具备本地运行、演示、联调和继续验收基础，但还不是 PRD 全量最终交付版本。本文档用于把当前上位机可联调能力转化为硬件伙伴可执行的接口、固件、测试和证据要求。

## 1. 背景和当前状态

星宿上位机当前已经完成以下本地能力：

- Web HMI 核心页面：实时监控、控制、AI、历史、审计、Modbus、系统配置。
- REST API、CLI、RBAC、审计链、SQLite 数据存储、CSV/XLSX/Markdown 导出。
- 控制安全门控：范围限制、单次步长限制、急停、人工锁、传感器超时、温度-转速安全禁区、独立 safety guard。
- 基础第三方接口：AINAS REST、MQTT bridge、Modbus RTU/TCP 映射和 Modbus TCP/TLS 本地路径。
- 本地性能冒烟：本地只读 API 和安全计算已通过短测。

当前仍需要硬件伙伴补齐的核心闭环：

- STM32 或等效控制器的最终 Modbus RTU 寄存器手册。
- 真实传感器、执行器、RS485 链路和反应釜整机联调记录。
- 急停、人工锁、执行器故障、传感器断线、CRC 错误、掉电恢复等异常工况证据。
- 硬件在环或实机控制闭环报告。
- 真实采集延迟、RS485 丢包率、7x24 或阶段性可靠性测试报告。

## 2. 目标

本 PRD 的目标是让硬件伙伴基于当前上位机状态完成可验收的硬件联调版本。

### 2.1 必须达成

- 上位机能够稳定读取温度、压力、搅拌转速、摇罐速度、流量、产物浓度和 pH 等关键点位。
- 上位机能够通过安全链路下发目标温度、目标搅拌转速、目标摇罐速度、目标压力和阶段时长。
- 硬件控制器必须对上位机命令做本地限幅和联锁，不能把上位机作为唯一安全保护。
- 真实硬件状态必须能被上位机判断为健康、过期、错误或离线。
- 任何危险或不可信状态下，系统必须默认进入安全态：停止危险动作、拒绝继续执行危险目标，并保留可追溯日志。

### 2.2 暂不要求

- 不要求硬件伙伴交付上位机 Web 页面、AI 算法、LoRA 模型或云端平台。
- 不要求硬件伙伴负责 AINAS、MQTT 平台账号和云端大模型验收。
- 不要求当前阶段证明 30 天工业连续运行，但需要提供可执行的长测方案和阶段性报告。

## 3. 系统边界

### 3.1 上位机负责

- 提供 HMI、REST API、CLI、审计、数据存储和导出。
- 根据配置和安全规则拒绝不安全目标。
- 通过 Modbus RTU/TCP 或 ESP32 Serial Bridge 与下位机交互。
- 对传感器新鲜度、设备健康、上一次控制写入结果和报警状态做软件侧判断。

### 3.2 硬件控制器负责

- 采集传感器数据并按约定协议上报。
- 接收上位机目标值并控制执行器。
- 执行本地硬件限幅、急停、互锁和故障保护。
- 明确报告命令执行成功、失败、拒绝和故障原因。
- 提供最终寄存器表、线缆接线图、固件版本、标定记录和联调日志。

## 4. 推荐硬件架构

### 4.1 首选路径：STM32 + Modbus RTU

- 物理链路：RS485。
- 默认串口：`/dev/ttyUSB0`。
- 默认参数：9600 8N1。
- 默认从站地址：1。
- 上位机配置来源：`config/device.toml`。

### 4.2 备选路径：ESP32 Serial Bridge

- 物理链路：ESP32 USB-Serial、UART 或 UART 转 RS485。
- 默认串口：`/dev/ttyUSB0` 或 `/dev/ttyAMA0`。
- 默认参数：115200 8N1。
- 上报频率：1 Hz。
- 帧格式：一行 ASCII 文本，字段使用 `|` 分隔，行尾 `\n`。
- 校验：`chk` 为 XOR 校验。
- 上位机配置来源：`config/device.esp32.toml`。

硬件伙伴如果选择 ESP32 路径，需要说明它是最终生产方案还是临时桥接方案。若最终生产仍使用 STM32 Modbus RTU，ESP32 只能作为联调过渡。

## 5. 数据采集需求

### 5.1 必选采集点

| 点位 | 单位 | 精度目标 | 默认上位机范围 | 备注 |
| --- | --- | ---: | --- | --- |
| 温度 | degC | +/- 0.1 | 0 到 250 | 生产安全上限另受 `config/safety.toml` 限制 |
| 压力 | MPa | +/- 0.01 | 0 到 10 | 必须明确是否为表压 |
| 搅拌转速 | rpm | +/- 1 | 0 到 2000 | 控制安全上限当前为 1200 rpm |
| 摇罐速度 | cpm | +/- 1 | 0 到 60 | 次/分 |
| 流量 | L/min | +/- 0.1 | 0 到 20 | 如硬件无流量闭环，需明确只读或估算来源 |
| 产物浓度 | percent | +/- 0.1 | 0 到 100 | 可先接入模拟值，但正式验收需说明传感器来源 |
| pH | pH | +/- 0.01 | 0 到 14 | 若当前设备不具备，需标注未接入 |

### 5.2 采样与新鲜度

- 最低上报频率：1 Hz。
- 上位机当前传感器超时窗口：6000ms。
- 超过超时窗口后，上位机会拒绝控制写入，并将实时数据接口置为不健康状态。
- 硬件侧不得在传感器离线时伪造新鲜值；必须报告故障或停止上报。

### 5.3 倾角说明

当前 ESP32 协议只要求硬件上报 `tilt_state` 二值量，取值 `0` 或 `1`。上位机里的 `tilt_angle` / `tilt_angle_deg` 可由软件拟合用于趋势图和报警展示，不代表硬件直接测得的模拟倾角。若硬件伙伴计划提供真实倾角传感器，需要单独提交量程、单位、精度和寄存器映射。

## 6. 控制需求

### 6.1 必选写入目标

| 控制目标 | 单位 | 当前上位机默认安全范围 | 当前单次步长 | 硬件侧要求 |
| --- | --- | --- | --- | --- |
| 目标温度 | degC | 20 到 160 | 2 degC | 需二次限幅，禁止越过硬件安全上限 |
| 目标搅拌转速 | rpm | 0 到 1200 | 50 rpm | 需二次限幅，禁止异常跳变 |
| 目标摇罐速度 | cpm | 0 到 60 | 待硬件确认 | 需明确启动、停止、限速策略 |
| 目标压力 | MPa | 0 到 10 | 待硬件确认 | 需明确泄压和超压保护 |
| 加热时长 | s | 0 到 3600 建议 | 待硬件确认 | 用于工艺阶段 |
| 保温时长 | s | 0 到 7200 建议 | 待硬件确认 | 用于工艺阶段 |
| 冷却时长 | s | 0 到 3600 建议 | 待硬件确认 | 用于工艺阶段 |

### 6.2 禁止工况

上位机当前配置中禁止高温弱搅拌组合：

| 名称 | 条件 | 原因 |
| --- | --- | --- |
| hot-low-stir | 温度 125 到 160 degC 且搅拌 0 到 350 rpm | 高温弱混合会在控制层被阻断 |

硬件控制器也必须内置等效或更保守的安全联锁。硬件侧不能因为上位机漏检、通信异常或缓存旧命令而执行危险目标。

### 6.3 急停和人工锁

- 急停必须是硬件优先级最高的联锁。
- 急停触发后，硬件必须停止危险执行器，并向上位机报告 `emergency_stop=true` 或等效状态。
- 人工锁触发后，上位机和下位机均不得执行自动控制或 AI 控制目标。
- 急停复位和故障复归必须可追溯，不能静默恢复自动控制。

### 7.6 功能码

当前上位机 Modbus TCP 本地路径支持：

- `01` Read Coils
- `02` Read Discrete Inputs
- `03` Read Holding Registers
- `06` Write Single Holding Register

硬件伙伴如需要 `04`、`05`、`15`、`16` 等功能码，必须提前提出并进入上位机变更评估。

## 8. ESP32 Serial Bridge 协议

如果使用 ESP32 作为桥接固件，上报帧格式如下：

```text
RX|v=1|seq=123|ms=456789|temp=175.4|pressure=0.21|stir_speed=450|shake_speed=30|tilt_state=1|flow_rate=2.5|chk=AB
```

必填字段：

| 字段 | 单位 | 说明 |
| --- | --- | --- |
| `v` | - | 协议版本，固定为 1 |
| `seq` | - | 自增序号 |
| `ms` | ms | 控制器启动后的毫秒数 |
| `temp` | degC | 温度 |
| `pressure` | MPa | 压力 |
| `stir_speed` | rpm | 搅拌转速 |
| `shake_speed` | cpm | 摇罐速度 |
| `tilt_state` | - | 0 或 1 |
| `flow_rate` | L/min | 流量 |
| `chk` | hex | XOR 校验 |

下行帧格式如下：

```text
TX|v=1|heat_time=300|hold_time=600|cool_time=180|target_temp=120.0|stir_speed=850|shake_speed=35|target_pressure=0.50|chk=CD
```

ESP32 收到 `TX` 后仍必须做本地限幅、急停检查和硬件联锁。

## 9. 设备健康和故障模型

硬件伙伴必须支持以下状态表达，具体可通过 Modbus 状态点、扩展寄存器或串口字段实现：

| 状态 | 含义 | 上位机期望行为 |
| --- | --- | --- |
| online | 控制器在线且帧有效 | 允许进入后续安全判断 |
| stale | 数据过期 | 拒绝控制写入 |
| frame_error | CRC、校验或帧解析错误 | 报警并拒绝使用该帧 |
| command_failed | 上次命令执行失败 | 锁存控制故障，关闭自动控制 |
| emergency_stop | 急停触发 | 立即拒绝所有危险写入 |
| manual_lock | 人工锁定 | 禁止自动/AI 控制 |
| actuator_fault | 执行器故障 | 报警并禁止继续下发相关目标 |
| sensor_fault | 传感器故障 | 报警并拒绝依赖该传感器的控制 |

命令失败后，硬件侧必须保留最近一次失败原因。上位机复归故障前，如果硬件仍报告命令失败或设备不健康，上位机应继续拒绝恢复自动控制。

## 10. 性能和可靠性要求

| 项目 | 目标 | 当前说明 |
| --- | --- | --- |
| 传感器上报频率 | >= 1 Hz | 当前联调最低要求 |
| 采集链路延迟 | < 100ms | 需要硬件实测报告证明 |
| 安全控制响应 | < 100ms | 上位机本地安全计算已短测，执行器链路需硬件证明 |
| RS485 丢包率 | < 0.01% | 需要工业环境或等效干扰测试 |
| 断线恢复 | 可恢复且不自动执行旧目标 | 需要 RS485 断线/重连报告 |
| 掉电恢复 | 不丢失危险状态，不自动执行旧目标 | 需要断电/重启恢复报告 |
| 连续运行 | 阶段目标 72 小时，最终目标 30 天 | 当前阶段至少提交 72 小时计划或阶段记录 |

## 12. 联调验收标准

### 12.1 P0 验收

| 编号 | 验收项 | 通过标准 |
| --- | --- | --- |
| P0-01 | RTU 实机读点 | 必选采集点可连续读取，数值单位和缩放正确 |
| P0-02 | 目标写入 | 写入目标温度、搅拌、压力、摇罐和阶段时长后，硬件正确解析并执行或安全拒绝 |
| P0-03 | 安全拒绝 | 超范围、禁区、急停、人工锁、数据过期时，上位机和硬件均拒绝危险动作 |
| P0-04 | 故障上报 | 断线、CRC 错误、传感器故障、执行器故障能被上位机看到并进入报警 |
| P0-05 | 命令失败锁存 | 硬件命令失败后，上位机不继续自动控制，必须人工或维护流程复归 |
| P0-06 | 审计和日志 | 每次关键写入、拒绝、急停和故障均能追溯到时间、命令和原因 |

### 12.2 P1 验收

| 编号 | 验收项 | 通过标准 |
| --- | --- | --- |
| P1-01 | 采集延迟 | 真实链路采集延迟 < 100ms 或给出项目可接受的偏差说明 |
| P1-02 | RS485 丢包率 | 等效测试丢包率 < 0.01% |
| P1-03 | 断线恢复 | 断线后进入安全态，恢复后不自动执行旧目标 |
| P1-04 | 掉电恢复 | 控制器重启后状态清晰，上位机不误判旧样本为新样本 |
| P1-05 | 连续运行 | 至少提供阶段性长测记录，无危险动作、无静默数据错误 |

## 13. 联调流程

1. 硬件伙伴提交最终寄存器手册草稿和固件版本。
2. 上位机侧根据寄存器手册确认 `config/device.toml` 是否需要调整。
3. 使用单板或硬件在环完成读点联调。
4. 完成写目标联调，验证正常写入和安全拒绝。
5. 完成急停、人工锁、传感器超时、CRC 错误、执行器故障等异常工况。
6. 完成性能、丢包率、断线恢复和阶段性长测。
7. 双方归档日志、截图、配置、固件版本、问题闭环和验收结论。

## 14. 当前开放问题

| 编号 | 问题 | 需要硬件伙伴确认 |
| --- | --- | --- |
| Q-01 | 最终控制器 | STM32 Modbus RTU 是否为最终生产方案，ESP32 是否仅作桥接 |
| Q-02 | 温度量程 | 上位机默认读点为 0 到 250 degC，安全控制为 20 到 160 degC，硬件最终上限是多少 |
| Q-03 | 压力控制 | 目标压力是否真实闭环控制，泄压策略和超压联锁如何实现 |
| Q-04 | 流量控制 | 流量是只读测量、泵控闭环还是估算值 |
| Q-05 | 产物浓度 | 是否有在线浓度传感器，若无是否允许阶段性置为未接入 |
| Q-06 | pH | 是否有 pH 传感器，采样频率和标定方式是什么 |
| Q-07 | 倾角 | 是否仅提供二值 `tilt_state`，还是提供真实角度 |
| Q-08 | 急停接线 | 急停是否硬件切断执行器电源，是否有状态反馈到控制器 |
| Q-09 | 故障码 | 是否能提供统一故障码寄存器或扩展状态字段 |
| Q-10 | 多设备 | 是否存在多反应釜、多站号或网关场景 |

## 15. 建议里程碑

| 阶段 | 输出 | 通过条件 |
| --- | --- | --- |
| M1 接口冻结 | 最终寄存器表、串口参数、固件版本 | 上位机配置可固定，不再频繁改地址 |
| M2 单点读写 | 传感器读点和目标写入日志 | 必选点位读写通过 |
| M3 安全联调 | 急停、人工锁、超限、超时、故障注入报告 | 危险动作均被拒绝或进入安全态 |
| M4 整机闭环 | 加热、搅拌、压力、摇罐等执行链路记录 | 指令到执行器动作可追溯 |
| M5 外部验收 | 性能、丢包率、断线恢复、阶段长测 | 满足 P0，P1 无阻塞问题 |
